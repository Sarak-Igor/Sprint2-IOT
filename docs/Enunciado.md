🏗️ Enunciado Técnico: Sprint 1 — Fundação do Ativo e Infraestrutura de Dados1. Visão Geral e ContextoO objetivo desta fase é criar o Gêmeo Digital (Digital Twin) inicial e a pipeline de ingestão de dados para monitoramento de motores elétricos industriais. A solução deve integrar IoT, Inteligência Artificial e Governança de Dados para viabilizar a jornada digital de ativos.  2. Regra Absoluta: Arquitetura "Agnóstica" e ReutilizávelO projeto não deve ser acoplado a um hardware ou motor específico.Camada de Abstração (Drivers): Deve existir uma interface clara para a entrada de dados. O sistema deve alternar entre um MockProvider (dados simulados/Wokwi), FileProvider (CSV/JSON) e OPCUAProvider (ambiente real) sem alterar a lógica de negócio.Configuração via Metadados: Parâmetros técnicos do motor (limites de temperatura, RPM nominal, etc.) devem ser carregados de arquivos de configuração, permitindo a reutilização do software para qualquer modelo de máquina.3. Pré-requisitos e Preparação de AmbientePara garantir a padronização e escalabilidade, o ambiente deve contar com:Ambiente de Desenvolvimento: VS Code com extensões para Python e Docker.Simulação IoT: Instalação do Wokwi ou PlatformIO para emulação de sensores.  Containerização: Docker e Docker Compose para subir instâncias locais de banco de dados e brokers de mensageria.Controle de Versão: Repositório privado no GitHub com estrutura de pastas seguindo o padrão Clean Architecture.4. Tecnologias SugeridasPara suportar a modularidade e as futuras integrações de IA, recomenda-se:  Linguagem: Python 3.10+ (devido ao suporte extensivo a IA e IoT).Modelagem de Dados: Pydantic para validação de esquemas e contratos de dados.Comunicação Industrial: asyncua (Python OPC-UA) ou bibliotecas MQTT para telemetria.Banco de Dados: PostgreSQL (com extensão TimescaleDB recomendada para séries temporais) ou Supabase.  Interface: FastAPI para o backend e React/Next.js para o dashboard inicial.  IA e Visão: OpenCV e PyTesseract/EasyOCR para o estudo inicial de leitura de placas.  5. Arquitetura Proposta (Separação Modular)A solução deve ser dividida nos seguintes módulos obrigatórios:Módulo de Ingestão (Adapters): Responsável pela conexão com a fonte de dados (OPC-UA, Sensores, Simulador).  Módulo de Processamento (Domain): Converte sinais brutos em unidades físicas e aplica o Dicionário de Termos OPC-UA (mapeamento de endereços de memória para nomes legíveis como current_A, voltage_V).  Módulo de Cadastro (Asset Manager): Gerencia o TAG, especificações técnicas e localização do motor.  Módulo de Conhecimento (IA Ready): Estrutura de pastas para documentos técnicos (PDFs/Manuais) visando a futura implementação de RAG (Retrieval-Augmented Generation).  6. Lista Detalhada de Entregáveis (Sprint 1)📋 Ingestão e IoTScript de Captura: Código capaz de ler dados de tensão, corrente, temperatura, rotação e vibração.  Conversor Métrico: Módulo que transforma sinais (ex: 4-20mA ou valores brutos) em unidades do SI.  Dicionário de Ativos: Arquivo de mapeamento (JSON/YAML) correlacionando as tags industriais aos atributos do sistema.📋 Gêmeo Digital e DadosSchema do Banco de Dados: Estrutura para armazenamento do cadastro técnico e histórico operacional.  Dataset de Base: Organização da primeira massa de dados coletados para estabelecer o baseline operacional.  Estrutura de Governança: Documentação dos critérios de organização e rastreabilidade dos dados.  📋 Interface e VisualizaçãoDashboard de Telemetria: Tela inicial exibindo o estado dos sensores em tempo real.  Painel de Cadastro: Interface para registro de novos motores, permitindo inserir dados da placa técnica.  📋 Inteligência Artificial (Preparação)Estratégia de Visão Computacional: Documento técnico definindo os campos da placa que serão extraídos via OCR na Sprint 2.  Base de Conhecimento RAG: Estruturação inicial de manuais e termos técnicos para alimentar o futuro agente conversacional.  Automação RPA: Scripts iniciais para registro automático de eventos e atualizações do ativo.  📋 Documentação de ProjetoRepositório GitHub: Estruturado com README detalhado e diagramas de arquitetura.  Cronograma de Implantação: Detalhamento das metas para as Sprints 2, 3 e 4.
